# LIMITATIONS

Append-only. Dated. Signed with your lane letter.

| Date | Lane | Entry |
|---|---|---|
| 2026-09-09 | A | **Cascade sizes are exponential-tailed, not power-law.** We set a day-1 realism gate expecting a power law, found the opposite via a Vuong likelihood-ratio test (exponential favoured at every x_min, p ~ 0), and report it rather than tuning to hit the target. The literature's power-law result is established for transmission-grid blackouts; this is a multi-sector urban lifeline network where it is not. Consequence: our system sits subcritical, so absolute cascade frequencies should not be read as calibrated to a real city. Relative comparisons between arms — which is what every result in this project rests on — are unaffected, because all arms run on the identical simulator. |
| 2026-09-09 | A | Power and water asset topology is **synthesised and geo-anchored**, not real. Asset-level utility data is not public in India. Road and facility counts follow the real city's shape. |
| 2026-09-09 | A | Layer physics is a **capacity-flow resolver, not hydraulics or power flow**. `wntr` and `pandapower` plug in behind `city/engine/physics.py` later. The cascade mechanism is the contribution; the hydraulics are not. |
| 2026-09-09 | A | Flood exposure uses **latitude as a proxy for elevation**, because elevation is not in the topology. |
| 2026-09-09 | A | Intervention costs are **abstract units**, not procurement reality. Ratios are defensible; absolutes are not. |
| 2026-09-09 | A | **Hazard intensities other than the flood are calibrated judgement, not measurement.** The monsoon is anchored to December 2015. heatwave, cyber and equipment_age are synthetic and their intensities were chosen to produce a stated operational profile — contingent outcomes for the first two, many small cascades for the third, which is the near-miss corpus generator. A different choice would move the absolute numbers in every table. Relative comparisons between arms are unaffected, because all arms run on the identical simulator. |
| 2026-09-09 | A | **Cascade speed still depends on tick size.** Ignition is now a rate per second and is tick-invariant, but a cascade advances at most one generation per tick, so a coarser tick lets more damage accumulate before restoration catches up. All evaluation is fixed at `tick_s = 300`. Results are not directly comparable across tick sizes, and we do not claim they are. |
| 2026-09-09 | F | **H3 is only partly tested.** It was pre-registered as strictly more damage prevented at every budget from 1 to 10; we ran one budget. Reported as partly tested rather than as a pass. |
| 2026-09-09 | F | **The oracle is greedy over a 30-candidate pool, not a true optimum.** It is an achievable ceiling and a lower bound on the best possible action set. The '% of oracle' column should be read as 'share of an achievable ceiling', not 'share of the theoretical maximum'. |
| 2026-09-09 | E | **The console is a replay of exported scenarios, not an operator console.** The six beats run off `console/data/demo.json` with no server and no network, which is what makes the demo safe; but there is no live ingest, no alert queue and no way to act on a real system. |
| 2026-09-09 | E | **The demo scenario is one seed chosen from eight**, scored on the same criterion and reported as such in the export. It is an illustration. The evidence is the held-out ablation in `eval/results/arms.md`, not the demo run. |
| 2026-09-09 | E/D | **No backup demo video is recorded**, and `EXECUTION.md` section 10 asks for one. The demo is a static page with no network or server, which is the reason the risk is low, but it is not zero and the mitigation is not in place. |
| 2026-09-09 | F | **Arm A5 (I³, Tsinghua) was not reproduced.** Published numbers only. Every table says so where the row would be, rather than the arm being quietly dropped. |
| 2026-09-09 | D | **There is no service.** `service/` holds the redaction boundary, the structured-logging setup, the tests and a runnable decision CLI — not the FastAPI app, WebSocket, persistence or migrations `EXECUTION.md` section 10 asks for. Deployment was pre-committed as the first thing to cut and it was cut. The consequence is honest rather than hidden: the console replays a file, so the demo needs no server, but there is no live ingest path and the `Frame` contract in `contracts/frames.py` describes a WebSocket protocol nothing currently speaks. It is kept and schema-emitted because it is the interface a deployment would need, not because it is implemented. |
| 2026-09-09 | B | **`inference/` imports `city.engine.state`** for `NodeState`/`WorldState`. `AGENTS.md` rule 2 says importing another lane's internals is a contract gap, and this is one: the observable-state reconstruction reuses the simulator's state containers rather than a shared contract type. It is a coupling, not a leak — no ground truth crosses — but it means the inference layer would not lift onto a different simulator without that module coming with it. |
| 2026-09-10 | C | **The rollout spans the remaining horizon in up to 40 blocks, not hop by hop.** A block is longer than one propagation hop, so multi-hop propagation inside a block is compressed and the rollout understates how far a fast chain travels within one block. Running it hop by hop over a 54-hour horizon would need ~216 generations and would miss the 2 s decision budget. The approximation is in the direction of under-stating reach. |
